Function: get_stac_layers()
get_stac_layers(mission, polygon, resolution = None, daterange = None, bands= None, max_cc= None, clip_raster= None, cloud_masking = None, indices = None , output = None, aggregator= None, topographic_features = None, stats = None, q = None)

---

1) Parameters:

**mission**  
- Both `name` and `alias` work. Must not be `None`.  
- See `Mission Specs` → `name` or `alias`.

**output**   
- To export, set a NetCDF path, e.g. `./results/test.nc`.

**polygon**  
- Polygon formats: `gpkg`, `geojson`, `kml`, `kmz`, `shp`  
- Can be geographic (WGS84) or projected (e.g., UTM).  
- Can also be WGS84 bbox list: `[xmin, ymin, xmax, ymax]` (NOT projected coords). useful tool: `http://bboxfinder.com/`  
- If you have a polygon with multiple features, only the first feature is used. For multiple areas, run `5_Batch_Processing.ipynb`.

**resolution**  
- If `None` → uses default resolution (see `Mission Specs` → `default_resolution`).

**daterange**  
- If `None` → every available date.  
- (1) Standard (single window): `["YYYY-MM-DD", "YYYY-MM-DD"]`
- (2) Seasonal (repeats across years): `["MM-DD", "MM-DD"]`  
  - Example vegetation season: `["04-01", "10-31"]`   
  - In seasonal mode, the window is applied to **all years** in the mission’s supported span.
- (3) Seasonal with explicit year control:  
  - `{"season": ["MM-DD", "MM-DD"], "years": "all"}`  
  - `{"season": ["MM-DD", "MM-DD"], "years": [2019, 2020, 2021]}` -> specific years
  - `{"season": ["MM-DD", "MM-DD"], "years": "2018-2024"}` -> year range

**bands**  
- If `None` → all mission bands (and SCL).  
- See `Mission Specs` → `bands`.

**indices**  
- If `None` → no indices.  
- See `Mission Specs` → `indices`.
- Check out for index explanation @ `https://www.indexdatabase.de/`

**clip_raster**  
- If `True`, raster is clipped to polygon area; if `False`, covers polygon bounding box.  
- Keep `False` if you plan co-registration (bbox shape works best).  
- After co-registration you can clip using `clip_stac()`.

**max_cc**  
- Maximum cloud coverage % from STAC metadata.  
- Keeping `100` is recommended for maximum availability.

**cloud_masking**  
- Scene Classification Layer masking (NOT s2cloudless threshold masking).  
- Keep `False` if you want to generate cloud mask cube and choose your own threshold (`2_cloud_mask_data_cube`).  
- Set `True` for quick/rough masking (example: large areas).

**stats**  
- If `None` → no stats cubes.  
- Creates additional data variables in the output dataset with the specified statistics.  
- See `Mission Specs` → `stats`.
- `mean_timeseries` calculates mean over the full time series; `mean_monthly` calculates mean for each month present in the time series; `mean_annual` calculates mean for each year present in the time series.
- ONE FOR ALL: `mean_all` generates `mean_timeseries` + `mean_monthly` + `mean_annual` (same for other stats).
- Disabled if `aggregator` is `NOT` `None`.

**aggregator**  
- Generates a single scene of either mean or median along the time dimension for each selected band and index.
- If `None` → no aggregation.  
- `mean` or `median`, not together.  
- See `Mission Specs` → `aggregators`.
- Disables `stats`.

**q**  
- `True` hides print outputs except progress bar.
"""

2) EXAMPLES

2.1) Sentinel 2

2.1.1) Sentinel-2 L2A — Vegetation season across all years (season mode)

Use case: Build a long-term vegetation-season time series (Apr–Oct) for all available years; compute temporal composites (timeseries + monthly + annual) and export.

{
  "parameters": {
    "mission": "sentinel-2-l2a",
    "polygon": "/dss/.../polygons/naryn_test.gpkg",
    "resolution": 10,
    "daterange": ["04-01", "10-31"],
    "bands": ["blue", "green", "red", "nir", "swir16", "swir22"],
    "indices": ["ndvi", "ndwi", "ndmi"],
    "max_cc": 100,
    "cloud_masking": false,
    "clip_raster": false,
    "aggregator": null,
    "stats": ["mean_all", "median_all"],
    "output": "/dss/.../results/s2l2a_vegseason_all_years.nc"
  }
}


2.1.2) Sentinel-2 L2A — Snow season (cross-year) with explicit year range

Use case: Build a winter-season time series (Nov–Mar) for a specific year range (useful for snow cover / alpine areas).

{
  "parameters": {
    "mission": "sentinel-2-l2a",
    "polygon": "/dss/.../polygons/alps_roi.gpkg",
    "resolution": 10,
    "daterange": {"season": ["11-01", "03-31"], "years": "2019-2024"},
    "bands": ["green", "red", "nir", "swir16", "swir22"],
    "indices": ["ndsi", "ndwi"],
    "max_cc": 100,
    "cloud_masking": false,
    "clip_raster": true,
    "aggregator": null,
    "stats": ["mean_annual", "max_monthly"],
    "output": "/dss/.../results/s2l2a_snowseason_2019_2024.nc"
  }
}


2.1.3) Sentinel-2 L1C — Fast preview composite (aggregator mean)

Use case: Quick look / visualization (single aggregated image) without running stats. When you don’t have a polygon file yet, uses a simple WGS84 bbox [xmin, ymin, xmax, ymax] and exports a NetCDF.

{
  "parameters": {
    "mission": "sentinel-2-l1c",
    "polygon": [11.558979, 48.124622, 11.609787, 48.146045],
    "resolution": 10,
    "daterange": ["2024-06-01", "2024-07-01"],
    "bands": ["blue", "green", "red", "nir"],
    "indices": ["ndvi"],
    "max_cc": 100,
    "cloud_masking": true,
    "clip_raster": false,
    "aggregator": "mean",
    "stats": null,
    "output": "/dss/.../results/s2l1c_quick_mean.nc"
  }
}


2.1.5) Sentinel-2 L2A — Update an existing NetCDF (append new dates)

Use case: You already have a cube on disk and want to extend it (e.g., add the newest month) without rebuilding from scratch.

{
  "parameters": {
    "update": "/dss/.../results/s2l2a_existing_cube.nc"
    "daterange": ["2024-06-01", "2024-07-01"],
    "max_cc": 100,
    "cloud_masking": false,
    "clip_raster": false,
    "aggregator": null,
    "stats": null,
  }
}
